# 知识库交互与演示登录改进

默认演示登录密码为 `DemoOnly!2026`，登录页已预填。五个演示账号沿用 README 中的名称与权限。已有本机容器账号的密码散列已同步，旧 Token 已撤销，并逐个记录审计；数据库、JWT 和模型密钥未改变。`var/compose/secrets/demo-password` 保存本机实际演示密码，初始化保留已有自定义值，不会靠再次 seed 修改现有密码。

知识库列表中的每个文档标题都能打开弹窗，查看 PDF、Word、TXT 或 Markdown 原件提取的完整文本；引用卡片的标题也能打开对应文档。预览不依赖搜索准备状态，保留原文下载与独立引用核验。预览显示文字，原始排版、图片和附件仍需下载原件；不提供扫描 PDF 的 OCR。

弹窗支持加载提示、失败重试、关闭取消请求和账号切换后清空内容。正文以普通文本渲染，文件中的 HTML 不执行。后端复用权限、大小、路径、解析和 SHA256 校验，不能通过修改文档 ID 查看内部或已删除内容。

| 页面名称 | 说明 | 保留的接口参数 |
| --- | --- | --- |
| 按意思查找 | 查找意思相近的内容，措辞不同也可匹配 | `vector` |
| 关键词与意思匹配 | 同时参考关键词和意思 | `hybrid` |
| 智能查找（推荐） | 综合匹配后按与问题的相关程度排列 | `hybrid_rerank` |

页面中的“索引”改为“搜索内容准备”，“重新索引”改为“更新搜索内容”。只是调整面向使用者的表达，算法及线上的工具参数不变，不据此宣称准确率提升。

旧开发库的一份已发布种子政策仍登记旧原件哈希。为保持历史版本，读取种子 Markdown 时可使用 `EA_DATA_DIR/knowledge-source-archive/<登记SHA256>.blob` 中的精确原件；归档不存在时保留原读取规则。归档必须留在运行目录、与登记哈希一致且不超过大小限制，损坏或路径逃逸会拒绝访问，不回退绕过校验。上传文档不读取此归档。已从对应 Git 历史恢复本机旧版原件并记录审计，没有改写已发布政策、退款事实或历史评估产物。

验证记录位于被 Git 忽略的 `var/test-results/`：

- `knowledge-preview-backend.xml`：90 项知识库、完整性和部署相关回归通过。
- `knowledge-preview-archive-backend.xml`：39 项预览、归档及完整性检查通过。它与前一组有重叠，不累加为完整套件数量。Windows 路径逃逸案例明确记录为解析结果故障注入，不声称创建了真实符号链接。
- `knowledge-usability/frontend.xml`：60 项前端测试通过；严格类型、格式和生产构建通过。
- `knowledge-usability/browser/results.json`：真实本地浏览器检查，覆盖默认登录、逐文档标题、全文、三种查找方式、引用标题及常见桌面分辨率。

运行已启动的容器服务时，可在项目根目录执行以下只读浏览器检查：

```powershell
cd frontend
npm run test:knowledge-browser
```

默认访问 `http://127.0.0.1:15173`。使用原生开发版时先启动 API 与前端，再设置 `EA_KNOWLEDGE_BROWSER_URL=http://127.0.0.1:5173`。检查仅允许 loopback，浏览器阻止登录和知识查询以外的写请求，不发送 Agent 消息、不创建退款、不调用聊天模型。需要本机 Edge 与已安装的前端开发依赖。

这些专项记录属于本次交互改进；Phase 9 的 1097 项完整回归和既有评估保持原执行时间与源码范围，不冒称本次重新全跑。

2026-10-15 补查了实际桌面窗口：Edge 的 `http://127.0.0.1:15173/knowledge` 标签页仍在运行旧版页面，标题为普通文字，页面仍显示“混合检索 + 重排”。点击浏览器的重新加载按钮并重新登录后，同一窗口显示新版标题按钮与“智能查找（推荐）”，点击“平台优惠券规则”已实际打开正文弹窗。站内切换页面或点击“刷新文档”只更新路由或列表，不会替换已经加载到内存中的旧版前端代码。

容器 Web 的页面入口现返回 `Cache-Control: no-store`，带内容指纹的 `/assets/` 文件保留缓存。发布新版后，已经打开的标签页仍需重新加载；登录凭证保存在页面内存中，重新加载后需要登录。此设置不强制刷新正在进行业务操作的页面。
