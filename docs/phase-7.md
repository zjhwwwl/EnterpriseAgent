# Phase 7：Vue 管理后台与真实 API 集成

## 实现范围

版本 0.7.0，新增 Vue 3 / TypeScript / Vite / Element Plus 后台，消费此前已实现的 FastAPI 契约。没有新增绕过 Service 的订单写入入口、第二个 Agent、独立 Worker 或公网服务。源代码与前端锁文件位于 `frontend/`，后端数据库迁移仍为 `0005_analytics`。

本阶段已实际完成前端构建、43 项前端单元/组件测试、21 项 API 回归，以及真实 Edge 的一条串行全流程（14 个检查点）。公开证据见[验证报告](../evals/results/phase7/report.md)，真实页面截图见[README Demo](../README.md#实际-demo-截图)。这些结果描述开发验收，不推导盲评、完整模型质量或生产部署成绩。

| 页面 | 实际能力与边界 |
| --- | --- |
| Agent 对话 | 自己的持久会话、分页多轮任务、显式发送、按真实任务状态展示回答/失败、工具步骤/用量、知识引用、退款确认/拒绝、显式恢复 |
| 订单与售后 | 可见订单分页、指定订单、商品/物流/退款资格；客户核对退款，客服/管理员审核和模拟完成；分析员无明细权限 |
| 企业知识库 | 可见文档列表与下载、vector / hybrid / hybrid_rerank 检索与来源核验；管理员上传、删除、重索引，区分登记成功和实际索引状态 |
| 运营分析 | analyst / admin 的授权目录、四类实际只读查询模板、SQL 编辑和显式执行、完整受限原始值、SVG 比例图、确定性报告和指标口径 |
| 任务历史 | 当前账号的分页任务、所属会话筛选、执行详情及关联会话跳转 |

自然语言分析导航只预填 Agent 草稿，最多 2000 字符，不自动创建会话、发送问题或调用模型。首次进入页面只读取所需列表/目录。没有预填虚构订单、聊天回答或运营数值，也没有 SSE/流式响应界面。

## 认证、状态与敏感操作

JWT、用户和有效期只保存在 Vue 响应式内存，不使用 localStorage / sessionStorage 持久化 Token。刷新页面需重新登录；401 和到期清理认证状态。客户端对前后身份变化进行检查，防止旧请求覆盖新登录页面；页面实例按账号/角色和路由区分。Vite 只绑定 loopback，代理仅接受本机 HTTP origin，浏览器不读取 DeepSeek Key、数据库 URL 或 JWT 签名秘密。

前端角色控制用于显示操作和提示。后端继续验证实时角色、订单归属、文档可见性、会话创建角色、审批绑定、有效期和 SQL 权限。任务 `failed`、`waiting_approval`、`running` 与 `completed` 分别显示；HTTP 200 不作为任务完成。知识上传的 201 表示原件登记，索引状态和 index_error_code 单独显示。

Agent 退款确认展示服务器生成的订单、金额、原因、备注、政策版本与截止时间，勾选核对声明后才能明确确认。`resume` 仅发送 task 关联的 approval_id 和布尔 confirmed，关闭弹窗不改变状态。恢复也是显式操作，可能继续调用模型。消息提交结果不明时暂停继续发送，用户刷新会话核对服务器持久任务；不会自动重复 POST。

订单页面将未决审批、原幂等键和决定保存在按账号 ID 区分的模块内 Map，页面切换后可继续核对，手动重试保持原参数。Map 仅在当前浏览器页面运行周期内存活，刷新即丢失；业务事务幂等、审计和重复退款规则仍由后端保障。客服审核、模拟完成、知识删除和重索引均有明确核对界面。

## 引用、Markdown 与金额

Markdown 由 marked + DOMPurify 安全渲染，禁用图片、iframe、表单及主动 HTML。引用原文采用文本插值，当前核验路径根据 chunk_id 构造并附带认证，不直接访问任意 citation_url。已保存的历史引用是任务产生时的快照；当前引用可能因删除、索引变化或权限返回错误，界面分别展示，不把历史原文当作重新验证。

人民币整数分用 BigInt 格式化，不先经浮点除法。分析原始十进制字符串完整保留在表格与图形悬停提示，比例坐标通过精确整数缩放。图表最多展示前 30 行，完整受限结果见表格；NULL 不绘制为零，截断提示保留。指标和时间窗口以返回目录及执行 SQL 为准，不推断业务变化原因。

## 本地运行

先按 [部署](deployment.md) 启动 FastAPI 与基础设施。前端需要 Node.js 24（`>=24.15.0 <25`）：

```powershell
.\scripts\frontend.ps1 -Mode Install
.\scripts\frontend.ps1 -Mode Run
```

浏览器访问 `http://127.0.0.1:5173`，使用 [README](../README.md) 的公开模拟账号。依赖、npm 缓存、TEMP 和构建产物留在 D 盘项目；不重新安装现有 Node.js 运行时。API 默认代理至 `http://127.0.0.1:8000`，脚本 `-ApiTarget` 可指定专用本机 API；注入的 `EA_WEB_API_TARGET` 只接受无凭据、路径或 query 的 HTTP loopback origin。

```powershell
.\scripts\frontend.ps1 -Mode Check
.\scripts\check.ps1
```

前端 Check 依次执行格式、Vitest、严格类型/Vite 构建及生产依赖 audit，单元测试 JSON 位于 `var/test-results/phase7-frontend-unit.json`；浏览器流程单独执行。`frontend/dist` 为本机构建产物，不表示已部署。后端默认检查仍要求真实 PostgreSQL 和 RAG，报告写入 `var/test-results/phase7.xml` / `phase7.json`。

完整浏览器业务流程须显式接受实际聊天模型调用：

```powershell
.\scripts\verify-frontend.ps1 -AllowLive
```

该脚本检查专用测试连接和角色，必要时向 `enterprise_agent_test` 增补模拟数据并用真实 CPU 模型重新索引可见文档；不会重置或修改开发库。Chroma 使用独立 `ea_frontend_test` 集合前缀，原件使用 `var/frontend-test`，测试 Redis 使用 DB 1。脚本启动本机 API 8001 和生产构建预览 5174；已有端口监听时拒绝覆盖，退出时只停止验证过身份的自有子进程。浏览器业务操作写入虚构测试记录，供应商调用可能消耗余额。首次数据准备实际索引五篇文档，聊天模型调用为零。

浏览器产物位于 `var/test-results/phase7-browser`，重复运行前按摘要哈希将上一轮证据保存在 `phase7-browser-trials`。测试的独立 JWT 秘密、原始日志和环境仍留在被 Git 忽略的 `var`，公开报告仅包含安全摘要。`-Prepared` 只跳过已验证的数据准备；`-ResumeTask <UUID>` 可读取同一测试库中既有、属于模拟客户的待审批任务，测试仍核对状态和审批。本次通过流程复用了前一轮的真实 Checkpoint，没有重新提交退款模型请求。

在完整业务流程已生成历史任务后，可单独重拍实际页面：

```powershell
.\scripts\verify-frontend.ps1 -ScreenshotsOnly
```

该模式关闭测试 API 的聊天模型，不执行 seed、索引准备、消息提交、任务确认/恢复或业务修改，只允许读取、公开模拟账号登录和授权只读 SQL。它依赖原有测试准备摘要及已保存的知识、退款、分析任务，不创建任务来填充截图。实际重拍通过，保存八张直接浏览器截图；每个页面在 1280、1366、1440 宽度均无横向溢出，消息/resume/recover/业务修改请求均为零，见[截图记录](../evals/results/phase7/screenshots.json)。这验证上述宽度的页面布局，不等于全分辨率或新一轮在线模型质量验证。

## 真实浏览器范围与失败记录

最终通过流程使用 1440 × 960 的真实 Edge headless 浏览器，未拦截 API 为 Mock、未替换聊天模型。14 个检查点覆盖环境就绪、客户订单归属和明确拒绝、重启后复用持久审批、Agent 确认、知识引用核验、多轮任务历史、客服审核与模拟完成、管理员上传/重索引/删除及政策来源保护、四个 SQL 模板、分析员权限和非法 SQL 拒绝，以及自然语言分析预填后明确发送。

订单页关闭预览不会确认退款，拒绝实际记录一次决定且不新增退款；Agent 勾选核对并确认后只创建 `pending_review`，订单状态未变。后续客服显式审核、模拟完成得到 `completed_simulated`，没有支付接口。临时 Markdown 文档实际索引代数由 1 更新至 2，删除返回 204；受政策保护文档删除返回 409。跨客户订单返回 404，分析员访问订单返回 403，原始业务表 SQL 返回 422。

公开重拍截图中的 `approval.png` 展示已完成任务的历史退款提交回执，保留提交时的 `pending_review`，不是新的待确认弹窗。TaskDetail 标明提交时状态，最新审核状态须在订单页读取；`citation.png` 展示认证来源核验。历史任务及回执不随后续客服操作改写，也不会因为重拍而生成新模型回答或业务决定。

四个 SQL 模板和自然语言分析均与另行发起的 canonical 只读 API 逐列逐行对照；这些请求不共享数据库快照。模板对照验证页面/API 集成，不能替代独立基表事实检验。自然语言场景带明确 schema/输出约束，三个模型任务为引导式开发烟测；不能将三个最终任务完成或全流程通过解释成盲测完成率、SQL 泛化质量或性能基准。

## 限制与下一阶段

- 使用虚构数据与公开模拟账号；不接真实支付或退款，不发布公网。
- JWT 与未决审批内存状态不跨刷新持久化，无自动 Token 续期或生产登录会话管理。
- 同步请求和人工刷新任务，不提供流式响应、独立 Worker、自动恢复调度。
- 图表展示受限数据，当前聚合 SQL 能力和退款 cohort 口径仍沿用 Phase 6，不代表开放式 SQL 语义正确性。
- 真实多意图退款提示曾只返回政策而未准备审批，保留该失败；单一请求成功不能替代独立意图/工具评估。
- 当前 Element Plus UI chunk 较大，Vite 超过 500 kB 警告仍存在；没有组件按需引入优化、桌面所有分辨率或负载基准证明。
- Linux 应用依赖、应用/前端镜像、全栈 Compose、GitHub Actions 和干净环境部署仍待 Phase 9；基础设施容器运行不替代这些验证。
- Langfuse tracing、扩大独立 NL SQL/任务/忠实度评估仍待 Phase 8；历史小样本烟测不宣称泛化成绩。

下一阶段为 Phase 8：扩展独立任务、工具、SQL 与回答忠实度数据集，记录可复现失败及真实使用量；按实际需要接入 tracing。
