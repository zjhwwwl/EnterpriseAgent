# 测试与 Evaluation

## 当前结果边界

Phase 1 提供基础工程自动化测试；当前没有业务、检索、模型、SQL 或 MCP Evaluation 数据集和评估结果。**本文件中的数据量与指标均为后续计划，不是已运行指标。**

基础测试入口：

```powershell
.\scripts\check.ps1
# 仅运行 pytest
.\.venv\Scripts\python.exe -m pytest
```

基础覆盖配置校验、SecretStr、应用生命周期、服务信息、健康检查、错误格式、请求 ID、CORS、文档开关和日志保护。测试日志不记录密码、模型 Key 或原始敏感输入。

HTTP 测试包含两种执行机制：进程内 ASGI 测试用于精确检查应用生命周期和错误契约；`tests/e2e/test_local_server.py` 通过真实 CLI 子进程启动服务，在本机 loopback 地址执行 HTTP 请求，验证启动入口与网络响应。另有独立子进程在非法 `EA_` 环境下导入纯工厂模块，验证导入不会提前读取配置。后者不表示使用非法配置启动应用也应成功。

`check.ps1` 将缓存和 TEMP/TMP 放项目 `var`，依次执行 Ruff lint、格式检查、pytest 和 `pip check`，JUnit 报告写入 `var/test-results/phase1.xml`。它不执行在线模型或数据库业务 Evaluation。

## 测试分层

| 层次 | 验证内容 | 真实依赖要求 |
| --- | --- | --- |
| 单元测试 | 规则、参数、状态转移、SQL AST、分块和指标计算 | 可以隔离外部接口；不作为集成证明 |
| 数据库集成 | Alembic、约束、事务、归属、幂等与并发 | 真实 PostgreSQL |
| 检索集成 | 解析、Embedding、Chroma、BM25、Reranker、引用 | 实际文档和索引 |
| Agent 流程 | 步数、重试、中断、拒绝、恢复 | 测试替身用于流程，真实模型另测 |
| MCP 集成 | 子进程连接、发现、调用、错误 | 真实官方 SDK Server / Client |
| SQL 集成 | 查询正确、只读账号、权限、超时 | 真实 PostgreSQL 与授权视图 |
| 浏览器流程 | 登录、对话、确认、知识库管理、图表 | 真实前端与后端 |
| 部署检查 | 干净环境启动、健康状态、数据持久化 | 实际 Docker 引擎与 Compose |

不把 SQLite 的通过结果当作 PostgreSQL 权限和事务验收；不把接口测试当作浏览器流程完成；不把服务配置存在当作服务运行证明。

## 数据集建设

数据集、模拟业务与参考答案均为可提交的模拟内容，不使用企业内部资料或客户信息。

| 数据集 | 初始目标 | 覆盖 |
| --- | --- | --- |
| RAG | 60 条 | 正常政策、多文档、边界条件、过期文档、证据不足 |
| Agent | 30 条 | 订单物流、退款资格、申请、拒绝确认、多轮任务 |
| SQL | 20 条 | 销售额、退款率、订单对比、商品排行、边界日期 |
| 安全与恢复 | 20 条 | 越权、参数错误、提示注入、重试终止、审批与故障恢复 |

每条用例计划包含 ID、输入、角色/用户、固定基准日期、预期行为、允许工具、相关来源或参考结果。RAG 标注相关文档与 Chunk；SQL 标注结果与指标口径；安全用例标注应拒绝的边界和不能发生的副作用。

业务数据用固定随机种子和指定基准日期生成，保证“最近七天”和“本月”可复现。检索分开发集与保留测试集，开发集调 Chunk、召回数和重排参数，最终报告使用保留集。

## 指标

| 指标 | 口径 |
| --- | --- |
| Recall@K | 参考相关证据在 Top K 中被召回的比例 |
| MRR | 第一个相关证据排名倒数的平均值 |
| nDCG@K | 依据标注相关度评价 Top K 排序质量 |
| 引用有效性 | 引用的文档/版本/Chunk 存在，位置可定位且当前用户可访问 |
| 证据支持 | 回答中的政策结论由引用内容支持；与引用存在性分开统计 |
| 任务完成率 | 预期业务结果成立，关键状态和副作用通过数据库确认 |
| 参数正确率 | 工具参数通过 schema 且符合用例意图和归属 |
| SQL 正确率 | 在固定数据库上结果与参考一致，指标口径正确 |
| 安全通过率 | 拒绝越权/危险操作，且没有禁止的数据库副作用 |
| 响应耗时 | 分别记录检索、重排、模型、工具和端到端耗时 |
| Token 消耗 | 实际 API usage；无调用或不可得时明确标记，而非补造 |

单靠引用存在不能证明回答正确。开放式回答的证据支持可使用明确人工标注标准；可选模型 Judge 的模型、提示和不确定性单独记录，不能与确定性的数据库断言混在一起。

## 检索对照实验

至少运行两组配置：

- A：纯向量检索。
- B：中文 BM25 + Vector，通过 RRF 融合并 Rerank。

比较时固定文档、Chunk、Embedding、数据集、Top K 和生成配置，记录额外候选数量与重排成本。两组使用相同机器与运行条件，避免把不同硬件或数据版本误当成算法提升。

检索实验可以不调用聊天模型；若要比较最终回答、引用支持和 Token，则必须实际运行相同生成模型。性能测试先预热本地模型，并记录冷启动是否包含在统计中。结果没有提升也如实保存。

## 关键业务与故障用例

- 当前客户查询自己的订单成功，查询其他客户订单拒绝。
- 同一退款参数并发提交只创建一笔申请和一个工单。
- 相同幂等键、不同参数被拒绝。
- 确认过期、属于其他用户、修改了金额或订单的 resume 被拒绝。
- 已创建申请但图 Checkpoint 未保存，恢复后复用原结果。
- 用户拒绝确认后，数据库没有新增退款和工单。
- 政策超期、缺少有效版本或订单资格不符时不创建申请。
- 模型网络暂时失败按上限重试；授权拒绝不重试。
- 无效工具名、参数、SQL 或超过步骤预算时终止并报告失败。
- SQL 写入 CTE、未授权表、系统关系、危险函数及多语句被拒绝。
- 分析账号即使绕过应用校验，也不能修改业务表。
- 删除/重索引后的旧 Chunk 不成为当前答案证据。

## 输出与可复现性

Phase 8 计划在 `evals/results/` 保存原始 JSON、汇总 CSV 和可阅读 Markdown。单次运行记录时间、Git Commit、数据集摘要、种子、基准日期、模型、依赖版本、检索参数、硬件、耗时、Token 与失败用例。

结果行区分 `passed`、`failed`、`skipped` 和执行错误。缺少 DeepSeek Key、本地模型、数据库或 Docker 条件时记录跳过原因，不计为成功。日志和报告不保存密钥；涉及用户数据的内容仍使用模拟资料。

示例结果文件和运行命令将在真实评估入口实现后加入。本阶段不提供空壳分数、预填性能表或虚构优化结论。
